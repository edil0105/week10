# 10-апта: толық еркін камера — тінтуір (yaw/pitch), дөңгелек (fov)

Файл: `main.cpp`. Құрастыру (репозиторий түбірінен):

```bash
cmake -S . -B build && cmake --build build && ./build/bin/cg
```

`glad` пен `stb` — `external/` бумасында.

> **WSL (WSLg):** WSLg-де GLFW курсорды терезе ортасына қайтара алмайды, сондықтан `GLFW_CURSOR_DISABLED` режимінде ығысу жиналып, камера өздігінен айнала береді. Сол себепті WSL-де (`WSL_DISTRO_NAME` бар болса) бағдарлама **сүйреу режимінде** басталады: курсор қалыпты, камера **сол жақ батырманы басып тұрып** тартқанда бұрылады. **M** — әдістемедегі FPS режиміне (курсор жасырын) ауыстыру.

Сахнада бағдар үшін: 8-аптадағы бес куб + еден-торы (X осі қызыл, Z осі көк), айналада 12 кубтан сақина, экран ортасында прицел. Тінтуір қозғалысы «шикі» (`GLFW_RAW_MOUSE_MOTION`) — жүйелік үдеусіз.

| Перне | Әрекет |

## Базалық бөлім

| Қадам | Іске асуы |
|---|---|
| 1. Айнымалылар | `yaw = -90`, `pitch = 0`, `lastX/lastY = 400/300`, `firstMouse = true`, `fov = 45` — файлдың басында, callback-терден жоғары. `<cmath>` қосылған |
| 2. Курсор | GLAD-тан кейін `GLFW_CURSOR_DISABLED`, `glfwSetCursorPosCallback`, `glfwSetScrollCallback` |
| 3. `mouse_callback` | `firstMouse` тексерісі, `yoffset = lastY - ypos`, `glm::radians`, pitch ±89° |
| 4. `scroll_callback` | `fov -= yoffset` (алға айналдыру — жақындату) |
| 5. Проекция | `glm::perspective(glm::radians(fov), ...)` — әр кадрда, тұрақты 45 емес |

Тексеру: камера кубқа қарап басталады, тінтуір дұрыс бағытта бұрады, жоғары қарағанда сахна жоғалмайды, дөңгелек жақындатады.

## 1-тапсырма: шектеусіз pitch

Тәжірибе үшін шектеудің екі жолы `if (pitchLimit)` ішінде тұр — **L** басқанда өшеді, қайта басқанда қайтады (қайта құрастырмай). Шектеу өшкенде `pitch` әр тінтуір қозғалысында консольге шығады.

**Нәтиже:** `pitch = 90.0` болғанда экран бір түсті болып қалды — тек фон түсі, бірде-бір куб та, еден-торы да жоқ (ортадағы прицел ғана қалады — ол view/projection-сыз, бірден NDC-де сызылады) (`screenshots/04-broken.png`). Сол кадрда `view[0][0] = -nan` шықты.

### Қорғауға жауап: қай есептеу NaN берді?

1. `cos(90°) = 0` → `dir.x = cos(yaw)·0 = 0`, `dir.z = sin(yaw)·0 = 0`, `dir.y = sin(90°) = 1`.
2. `camFront = (0, 1, 0)` — `camUp`-пен **дәл бірдей** (параллель).
3. `glm::lookAt` ішінде камераның оң жағы `s = normalize(cross(f, up))`. Параллель векторлардың векторлық көбейтіндісі нөл: `cross((0,1,0), (0,1,0)) = (0,0,0)`.
4. `normalize((0,0,0)) = 0 / 0 = NaN`. Сол NaN бүкіл `view` матрицасына тарайды, шейдердегі `uProjection * uView * uModel * pos` да NaN болады — GPU бірде-бір үшбұрышты сыза алмайды, экранда тек `glClearColor` қалады.

**Нақты float-та байқалған нәрсе:** `cos(glm::radians(90.0f))` дәл 0 емес, `-4.37e-8` береді. Сондықтан `camFront`-та өте кішкентай `x` пен `z` қалады. Камера `(0, 0, 3)`-те тұрғанда бұл кішкентай сан `camPos + camFront` қосындысында сақталып, `lookAt` әлі де жұмыс істейді. Ал камера сәл жылжыса (скриншотта `camPos = (0.5, 0, 3)`), `0.5 + 1.9e-15 = 0.5` — кішкентай бөлік жұтылып, бағыт дәл `(0,1,0)` болады да, NaN шығады. 90°-тан **асып** кеткенде (`90.1`, `95` …) `cos` теріс болады, камера «шалқасынан» аударылып, сахна төңкеріліп көрінеді. Екі жағдай да қате, сондықтан шектеу ±89°.

Тәжірибеден кейін шектеу қайтарылды: әдепкі күйде `pitchLimit = true`.

## 2-тапсырма: sensitivity

Таңдалған мән: **`sensitivity = 0.1f`** — бір толық айналым (360°) шамамен 3600 пиксель, яғни экранның екі еніндей: нысанаға дәл қарауға жеткілікті баяу, бірақ артқа бұрылу үшін тінтуірді көп көтеру керек емес.

| Мән | 360° үшін тінтуір жолы | Әсері |
|---|---|---|
| 0.03 | 360 / 0.03 = 12 000 px | тым баяу, тінтуірді бірнеше рет көтеріп қою керек |
| 0.1 | 360 / 0.1 = 3 600 px | ыңғайлы |
| 0.5 | 360 / 0.5 = 720 px | тым сезімтал, кішкене қозғалыстан камера секіреді |

### Қорғауға жауап

- **Неге `const`?** Мән бағдарлама жұмыс істеп тұрғанда өзгермейді. `const` оны кездейсоқ өзгертуден қорғайды, оқитын адамға «бұл тұрақты баптау» екенін көрсетеді, компилятор оны тікелей санмен алмастыра алады.
- **Жаһандық етіп, пернемен өзгертуге бола ма?** Иә. `const`-ты алып, `float sensitivity = 0.1f;` деп файлдың басына шығарамыз да, `processInput`-та мысалы `+` / `-` пернелерімен (бір рет басу әдісімен) өзгертеміз. Тек 0-ден үлкен болуын шектеу керек.

## 3-тапсырма: Invert Y

```cpp
bool invertY = false, iPressedLast = false;
// processInput:
bool iNow = glfwGetKey(window, GLFW_KEY_I) == GLFW_PRESS;
if (iNow && !iPressedLast) invertY = !invertY;
iPressedLast = iNow;
// mouse_callback:
float yoffset = lastY - (float)ypos;
if (invertY) yoffset = -yoffset;
```

Бұл әдіс `keyPressedOnce()` функциясына жиналып, I, P, R, L, F12 пернелерінің бәрінде қолданылады.

### Қорғауға жауап

- **Алдыңғы күйді сақтамасақ?** `processInput` әр кадрда шақырылады. Перне 0.2 с басулы тұрса, 60 FPS-те `invertY` 12 рет ауысады — соңғы күй кездейсоқ болады.
- **Неге WASD-та бұл мәселе жоқ?** WASD — үздіксіз әрекет: басулы тұрған **әр кадрда** камера `speed * dt` қашықтыққа жылжуы керек. Ал ауыстырғыш (toggle) басу сәтінде бір рет қана орындалуы тиіс.

## 4-тапсырма: камера күйі (P)

```
camPos   = (0.00, 0.00, 3.00)
camFront = (0.00, 0.00, -1.00)
yaw = -90.0   pitch = 0.0   fov = 45.0
length = 1
```

Тінтуірді қозғап, P-ні бірнеше рет басқанда `length` әрқашан 1-ге тең немесе соған өте жуық.

### Қорғауға жауап

- **Неге дәл 1.0 емес?** `float`-та ~7 мәнді цифр ғана бар. `cos`, `sin`, көбейту, `sqrt` — әрқайсысы дөңгелектеу қатесін қосады, сондықтан ұзындық соңғы цифрда ауытқиды.
- **`normalize`-ды алып тастасақ?** Математикада ұзындық бәрібір 1: `cos²p·(cos²y + sin²y) + sin²p = cos²p + sin²p = 1`. Сондықтан ұзындық айтарлықтай өзгермейді, тек float қатесі сәл көбірек болуы мүмкін. Әр кадрда бағыт yaw/pitch-тен **жаңадан** есептелетіндіктен, қате жиналмайды. `normalize` — сақтандыру.

## 5-тапсырма: fov шегі 90°

`FOV_MAX = 90.0f`. Дөңгелекті артқа айналдырып 90°-қа жеткізгенде сахна алыстап, кең көрінеді, ал экранның шетіндегі кубтар созылып, қиғашталып кетеді.

### Қорғауға жауап: үлкен fov неге «созады»?

Бұл қате емес — **перспективалық проекцияның қалыпты қасиеті**. 7-аптадағы проекция матрицасы нүктені `z`-ке бөледі: камера осінен `α` бұрышта тұрған нүкте экранда `tan(α) / tan(fov/2)` қашықтықта шығады. Үлкен сфераны **жалпақ** экранға проекциялаймыз, ал `tan` шетке қарай тез өседі (туындысы `1 / cos²α`). fov = 90° болғанда экранның шеті α = 45°-та, сол жерде объект ортадағыдан шамамен 2 есе созылады. Кіші fov-та (45°, 25°) барлық көрінетін бұрыштар кішкентай, `tan α ≈ α`, сондықтан бұрмалану байқалмайды. Шын фотокамераның кең бұрышты объективі де осылай «бұрмалайды».
